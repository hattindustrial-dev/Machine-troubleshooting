Module directory

Every route in this hub is tagged with the component types it applies to (pump, bearing, coupling, seal, gearbox, lubrication system, pneumatic, motor). That tagging is the foundation for facility mode.

Build a machine. A maintenance manager describes a machine as a chain of components: motor, coupling, gearbox, pump, mechanical seal, centralized grease system. Each component is picked from the module library, with the plant's own details attached: make and model, bearing part numbers, seal plan, lubricant, alignment tolerance, set pressures, and the equipment number from the CMMS.

Filter the diagnosis. When a technician opens that machine and picks a symptom, the hub only shows routes that apply to the components in that chain, and the result cards carry the plant's own specifics: the actual grease quantity for that bearing, the actual seal flush plan, the actual regulator set point. Generic content becomes plant-specific procedure without anyone rewriting it.

Capture what happened. Each diagnosis can be logged against the machine with readings, photos, and the route taken. Over time the machine builds its own history, and recurring routes point at root causes a work order system never surfaces.

Train on it. Every module has a Self-Check tab with questions grouped by the tab they test. A supervisor can assign a module, ask for the self-check to be worked through with the reasons read, and walk the machine with the technician afterward. In facility mode the questions can be filtered to the components a technician actually maintains.

The modules stay universal. The facility layer is a filter and an overlay on top of them. That is why the hub is built as tagged data rather than a fixed page.
