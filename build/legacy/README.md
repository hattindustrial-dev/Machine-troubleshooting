# The original build scripts

These are the scripts the BuiltWright files were generated by, kept as history. They do
not run the project any more and nothing in `build/` calls them.

They are here because they are the record of how the content was made, and because two of
them are still the authority on decisions that outlived them: the PM task interval
heuristic and the component grouping in `build_tools.py`, and the ten pocket cards written
as a Python list in `pass3.py`. Both of those were read back out and ported, and
`build/derive.mjs` checks the PM library still reproduces exactly from the module data.

## Why they no longer run

They read the module HTML and rewrote it in place. The modules are shells now: the content
lives in `app/data`, the behaviour in `app/bw-renderer.js`, and the pages are generated by
`build/cutover.mjs`. Running these scripts against the current app would find almost
nothing to work on, and `build_tools.py` would overwrite `sw.js` with a precache list that
misses every data file.

They also carry the absolute paths of the sandbox they were written in
(`/mnt/user-data/outputs/` for the app folder, `/home/claude/pt_styles.html` for the style
block), so they would not run as they stand in any case.

## What replaced them

| was | now |
| --- | --- |
| `build_tools.py` PM library | `build/derive.mjs`, from the module data |
| `build_tools.py` search index | `build/derive.mjs`, from the module data |
| `build_tools.py` sw.js | `build/sw.mjs` |
| `build_tools.py` integrity checks | `build/validate.mjs`, with more of them |
| `pass3.py` series index | `build/extract.mjs` and `build/validate.mjs` |
| `pass3.py` pocket cards | `app/data/pocketcards.js` |
| `pt_styles.html` head and CSS | `app/bw.css` plus each module's own blocks |
| `add_selfcheck.py`, `qbank*.py` | the self-check banks are in the module data |
| `review_pass.py`, `older_modules_parity.py` | `build/validate.mjs` |

Three of the bugs found during the migration came from regexes in these scripts that
needed `label:` and `text:` adjacent on one line, or a route id beginning with `r_`. The
counts they produced were wrong in ways nothing noticed for as long as they were the only
check. That is the argument for the structural checks that replaced them, not an argument
against the scripts, which built the whole thing.
